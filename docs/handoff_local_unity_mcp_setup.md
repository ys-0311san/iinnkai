# 引き渡し手順書: ローカル Claude Code で VRChat + UnityMCP 環境を立ち上げる

> **宛先: ユーザーのローカル PC（Windows）で動作する Claude Code**
> **作成: クラウド側 Claude Code セッション（2026-09-07）**
>
> 背景と設計方針は `docs/spec_vrc_declarative_builder.md` を参照。
> このファイルはその **Phase 0（環境検証）を実際に手元で実行するための指示書**。

---

## 0. ゴール

1. VCC で VRChat ワールド用の検証プロジェクトを作る
2. Unity を起動する
3. UnityMCP を接続し、Claude Code から Unity Editor を操作できる状態にする
4. **Phase 0 の合否を判定する** — Editor スクリプトから `TryGetBuilder<IVRCSdkWorldBuilderApi>` が成功するか

**4 が本命。**ここが通らなければ、宣言的ワールド構築ツールの設計は前提から見直しになる。1〜3 はそのための土台。

---

## 1. このタスクを実行するエージェントへの制約

**必ず守ること。**

### 1.1 推測でコマンドを打たない

`vpm` / `Unity.exe` / UnityMCP のサブコマンドやオプションは、**必ず `--help` や `--version` で実際の仕様を確認してから**使う。記憶やネット上の記事を根拠にコマンドを組み立てない。バージョン差でオプションが変わっている可能性が高い。

### 1.2 ネット検索は原則しない

参照してよいのは以下のみ。それ以外を見る必要が生じたら、**実行前にユーザーへ確認を取る**。

- `https://github.com/orange3134/resoloop`
- ユーザーが URL を明示的に指定したリポジトリ
- VRChat 公式ドキュメント（`creators.vrchat.com` / `vcc.docs.vrchat.com`）— 必要になった時点で 1 回ずつ確認を取る

理由: エージェントに PC 操作権限がある状態で外部コンテンツを広く読むと、プロンプトインジェクションの経路になる。読む面を絞ることが安全性の担保になっている。

### 1.3 破壊的操作の禁止

以下は **ユーザーの明示的な承認なしに絶対に実行しない**。

- ワールド／アバターの **アップロード**（`BuildAndUpload`、SDK パネルの Publish ボタン含む）
- **既存の** Unity プロジェクトの変更・パッケージ更新
- Unity / Unity Hub / VCC 本体のバージョン変更やアンインストール
- 既存プロジェクトの `Packages` / `ProjectSettings` の書き換え

**新規に作ってよいのは、この検証専用のプロジェクト 1 つだけ。**

### 1.4 認証情報を扱わない

VRChat SDK へのログインは **ユーザー本人が GUI で手入力する**。エージェントは VRChat のユーザー名・パスワード・トークン・セッション情報を、読み取らない・書き込まない・ファイルに残さない。該当ステップに来たらユーザーに操作を依頼して待つ。

### 1.5 ステップを飛ばさない

各ステップの **完了条件** を満たしてから次へ進む。満たせない場合は**そこで止まり、エラーの原文を添えて報告する**。回避策を勝手に試して先に進まない。

## 2. STEP 1 — 環境の棚卸し

まず現状を把握する。**この段階では何も変更しない。**

以下を調べて一覧にする。見つからない場合は「なし」と記録すること（推測で埋めない）。

| 項目 | 調べる内容 |
|---|---|
| OS | Windows のバージョン |
| Claude Code | バージョン |
| VCC (VRChat Creator Companion) | インストール済みか、バージョン |
| `vpm` CLI | PATH にあるか。あれば `vpm --help` の出力 |
| Unity Hub | インストール済みか |
| Unity | **インストール済みの全バージョン**（VRChat SDK はバージョン固定のため重要） |
| VRChat 本体 | `VRChat.exe` のフルパス |
| .NET SDK | `dotnet --list-sdks` の結果（resoloop を将来使う場合に必要） |
| 既存の VRChat プロジェクト | あるか。**あっても触らない**。衝突回避のため把握だけする |

**完了条件:** 上記の表を埋めてユーザーに報告し、次へ進む承認を得る。

## 3. STEP 2 — UnityMCP の特定

**ここで一度止まる。**

### 2.1 ユーザーに聞く

「UnityMCP」は同名・類似名の実装が複数存在する。**どれを使うのか GitHub の URL をユーザーに確認する。**

### 2.2 README だけを読む

URL を得たら、そのリポジトリの README（および必要ならインストール手順のドキュメント）**のみ**を読む。以下を整理して報告する。

- **提供される MCP ツールの一覧**
- 特に次の機能の有無（設計上の分岐点になる）
  - [ ] シーン階層の読み取り
  - [ ] GameObject の作成・削除・親子付け
  - [ ] Component の追加・削除・プロパティ設定
  - [ ] Unity のメニュー項目の実行
  - [ ] Console ログの取得
  - [ ] 任意 C# コードの実行
- **通信方式**（Editor 拡張＋ローカルサーバ？ 使用ポートは？ 外部に通信するか？）
- **対応 Unity バージョン**
- **VRChat SDK との既知の競合の有無**

### 2.3 安全性の確認

- 外部ネットワークへ通信する機能があるか。あれば内容をユーザーに報告する
- 任意 C# 実行機能がある場合、その危険性をユーザーに明示する

**完了条件:** 上記を報告し、導入してよいかユーザーの承認を得る。

## 4. STEP 3 — 検証用プロジェクトの作成（VCC）

### 3.1 Unity バージョンを決める

**VRChat SDK が要求する Unity バージョンに合わせる。**STEP 1 で確認したインストール済みバージョンと突き合わせ、一致するものがなければ**ユーザーに追加インストールを依頼して待つ**（エージェントが勝手に入れない）。

### 3.2 プロジェクトを作る

`vpm` CLI か VCC の GUI で、**ワールド用テンプレート**の新規プロジェクトを作る。

- サブコマンドは `vpm --help` で実際に確認してから使う
- プロジェクト名は用途が分かるものにする（例: `VRCLoopSandbox`）
- 作成場所はユーザーに確認する。既存プロジェクトのあるフォルダには作らない

**完了条件:** プロジェクトフォルダが生成され、`Packages` に VRChat Worlds SDK が入っている。

## 5. STEP 4 — Unity の起動

Unity Hub 経由、または `Unity.exe` に `-projectPath` を渡して起動する。オプションは `Unity.exe --help` 相当で確認する。

初回はパッケージのインポートとコンパイルに時間がかかる。**完了を待つ。**

**完了条件:**
- エディタが開いている
- Console に **コンパイルエラーが 0 件**（Warning は可）
- メニューバーに `VRChat SDK` が出ている

エラーが出ている場合は**原文をそのまま報告して止まる。**

---

## 6. STEP 5 — VRChat SDK の初期設定

`VRChat SDK > Show Control Panel` でコントロールパネルを開く。

1. **Authentication タブ — ユーザー本人がログインする**
   → エージェントはここで**操作せず待機**。完了したかユーザーに確認する（§1.4）

2. **Settings タブ** — `VRChat Client` に `VRChat.exe` のパスを設定
   → STEP 1 で調べたパスを使う

3. **Builder タブ**
   - `Setup Layers for VRChat` を実行
   - `Set Collision Matrix` を実行

**完了条件:** Builder タブに表示されている問題が解消し、**`Build & Test` ボタンが押せる状態**になっている。

> **注意:** ここで `Build & Test` を押すと VRChat クライアントが起動する。まだ押さなくてよい（STEP 8 で使う）。**Publish / Upload は絶対に押さない。**

## 7. STEP 6 — UnityMCP の導入と接続

STEP 2 で確認した README の手順に従う。一般的には次の2つが必要になるはず（実際の手順は README を優先）。

1. Unity 側にパッケージ／Editor 拡張を入れる
2. Claude Code 側の MCP サーバ設定に登録する

**完了条件（この 3 つ全て）:**
- Claude Code から **UnityMCP のツールが見えている**
- Unity Editor 側に接続済みの表示が出ている
- **シーン階層を実際に取得できた**（下の STEP 7 で確認）

## 8. STEP 7 — 往復の動作確認

最小の往復を通して、経路が本当に生きているか確かめる。

| # | やること | 期待される結果 |
|---|---|---|
| 1 | UnityMCP 経由でシーン階層を取得 | 現在のシーンの内容と一致する |
| 2 | UnityMCP 経由で空の GameObject を1つ作る | Unity の Hierarchy に出現する |

## 9. STEP 8 — Phase 0 の合否判定【最重要】

**ここが本命。**Public SDK API に到達できるかを確かめる。

### 8.1 確認したいこと

Editor スクリプトから次が成功するか。

```
VRCSdkControlPanel.TryGetBuilder<IVRCSdkWorldBuilderApi>(out var builder)
```

これが `true` を返せば、ビルド／アップロードをスクリプトから制御できる＝設計の前提が成立する。

### 8.2 注意点

- **`TryGetBuilder` は SDK コントロールパネルが開いていないと `false` を返す。**必ず開いた状態で試すこと
- アセンブリ定義参照が必要な場合がある（ワールドは `VRC.SDK3.Editor`、共通は `VRC.SDKBase.Editor`）
- **検証は `Build & Test`（ローカルビルド）まで。`BuildAndUpload` は呼ばない**

### 8.3 実装について

**この Editor スクリプトの作成はユーザーの運用ルール上 Codex CLI の担当。**
ローカルの Claude Code は、
1. 何を確認したいか（上記）を仕様として整理し
2. ユーザーに Codex への依頼を促し
3. 出てきたコードを**レビューしてから**適用する

という流れを取ること。**エージェントが自分で C# を書き下ろさない。**
（ただしユーザーが「書いていい」と明示した場合はその限りではない）

### 8.4 判定

| 結果 | 意味 | 次のアクション |
|---|---|---|
| `true` が返る | **Phase 0 合格。**設計の前提が成立 | Phase 1（シーン階層のダンプ）へ進める |
| `false` が返る | パネル未オープン等の可能性 | 条件を変えて再確認 |
| 例外・型が見つからない | SDK バージョン差の可能性 | **止まって報告。**設計の見直しが必要 |

## 10. STEP 9 — 実機ループの確認（任意）

余力があれば、resoloop 相当の反復ループが成立するかも見ておく。

1. シーンに Cube を1つ置く
2. Builder タブで **クライアント数を 0** にする → ボタンが `Build & Reload` に変わることを確認
3. VRChat クライアントを `--watch-worlds` 付きで起動しておく
4. `Build & Reload` を実行 → **起動済みクライアントが新しいビルドへ移動するか**

これが動けば、「ワールドを編集 → 数十秒で実機に反映」のループが手に入る。resoloop の体験に最も近い部分。

参考の起動オプション（要検証）:
```
VRChat.exe --watch-worlds --profile=0 --no-vr --enable-debug-gui --enable-sdk-log-levels --enable-udon-debug-logging -screen-width 1920 -screen-height 1080
```

## 付録: 安全上の注意まとめ

- ✋ **アップロードしない** — `BuildAndUpload` / Publish ボタンは承認なしに触らない
- ✋ **既存プロジェクトを触らない** — 検証は新規プロジェクトのみ
- ✋ **認証情報を扱わない** — VRChat へのログインはユーザーが手で行う

- ✋ **クライアント改造は論外** — VRChat の実行中プロセスへの介入は BAN 対象（`spec_vrc_declarative_builder.md` §2 参照）
